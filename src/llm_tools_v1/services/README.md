# 服务层命名规范与 bid/bidding 区分说明

## 1. bid 与 bidding 的英文语义区别
- **bid**
  - 名词：投标、报价、出价，通常指一次具体的"出价"或"投标行为"。
  - 动词：投标、出价。
  - 适用于"动作"或"结果"。
- **bidding**
  - 名词：招标、投标过程、招标活动，通常指"招标"这一完整的过程或活动。
  - 适用于"过程"或"整体事件"。

## 2. 业务建模中的推荐用法
- **bidding**：用于表示"招标公告""招标项目""招标活动"等整体过程或实体。
  - 例如：`Bidding`（招标公告主表）、`bidding_service.py`（招标业务服务）
- **bid**：用于表示"投标""中标""报价"等具体行为或结果。
  - 例如：`BidAwardPrice`（中标价格）、`bid_award_price_service.py`（中标价格服务）

## 3. 项目内命名规范
- 服务层文件统一采用下划线分隔（snake_case）+ service结尾，业务对象优先全拼，避免缩写和歧义。
- 招标相关统一用 `bidding` 前缀，如：
  - `bidding_service.py`：通用招标公告相关服务
  - `bidding_csg_service.py`：CSG（南方电网）专用爬虫/业务服务
- 投标/中标相关统一用 `bid` 前缀，如：
  - `bid_award_price_service.py`：中标价格相关服务

## 4. 示例表格
| 业务对象         | 推荐英文前缀 | 说明                   |
|------------------|-------------|------------------------|
| 招标公告/项目    | bidding     | 招标过程、公告、主表   |
| 标包             | bidding     | 属于招标下的子项       |
| 投标/中标/报价   | bid         | 投标行为、结果、价格   |

## 5. 其他建议
- 文件名与类名、schema名保持语义一致，便于查找和维护。
- 若未来有更多服务，均采用 `业务对象_service.py` 格式，保持一致。
- 避免缩写（如 csg 必须用时可全拼或加注释）。
